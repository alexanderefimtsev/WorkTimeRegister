# WorkTimeRegister

Desktop-приложение для регистрации рабочего времени и перерывов. Данные сохраняются локально в SQLite.

Приложение позволяет:

- начинать и завершать рабочий день, переключать работу и перерывы внутри него;
- ставить активную работу или перерыв на паузу и продолжать тот же режим;
- видеть итоги за день и длительность активного периода;
- переносить указанное время между работой и перерывами;
- добавлять, убирать и полностью очищать время работы или перерыва;
- просматривать журнал действий с фильтром по датам;
- экспортировать выбранный период журнала в JSON и импортировать его обратно.

Основные действия доступны на панели инструментов. В карточках работы, перерывов и
текущего периода находятся быстрые команды добавления, вычитания и очистки времени.
Время на паузе не включается в итоги работы, перерыва и активного периода.

## Рабочий день

Кнопка «Начать рабочий день» открывает сегодняшний день и сразу запускает работу.
Кнопка «Закончить рабочий день» закрывает текущий период и паузу. Переключение
работы и перерыва доступно только внутри открытого дня. Повторное начало в ту же
дату продолжает тот же день: накопленные итоги сохраняются, а время между завершением
и повторным началом не учитывается.

Красный крестик скрывает главное окно, сохраняя учёт. Полный выход через «Выйти»,
системное Quit или Cmd+Q завершает рабочий день и сохраняет последний режим и паузу.

В диалоге «Настройки» доступны три опции управления рабочим днём, изначально выключенные:

- «Начинать рабочий день при запуске программы» — если сегодня день ещё не начинался,
  запуск программы открывает его в режиме работы.
- «Восстанавливать день при повторном запуске» — сегодняшний день, завершённый выходом
  из программы, возобновляется с последним режимом и состоянием паузы. Время вне программы
  не учитывается. День, завершённый вручную, автоматически не восстанавливается.
- «Продолжать рабочий день после полуночи» — на границе суток закрываются день и период,
  затем открываются новый день и новый период с прежним режимом и паузой. Текущий период
  и итоги нового дня начинаются с нуля. Без этой опции учёт в полночь останавливается.

Дополнительно доступны настройки сна:

- «Приостанавливать учёт во время сна компьютера» — включена по умолчанию. Перед сном
  работа или перерыв ставятся на паузу. Если её выключить, время сна учитывается в текущем режиме.
- «Продолжать автоматически после пробуждения» — выключена по умолчанию. Снимает только
  автоматическую паузу сна; ручная пауза сохраняется. Завершённый день не открывается заново.

При включённом продолжении через полночь пауза переносится на следующие сутки: сон на несколько
дней не превращается в несколько полных рабочих дней. При выключенном продолжении день
закрывается в полночь, и пробуждение само по себе не начинает новый день.

Если при включённой паузе сна программа более 60 секунд не обновляла контрольную отметку,
а период был активен и уведомление о сне отсутствует, она предлагает отдельно решить,
как учитывать неизвестный интервал. Разрыв сам по себе не считается доказательством сна
или сбоя. До выбора итоги заморожены. При уже включённой паузе и закрытом дне вопрос не возникает;
при выключенной паузе сна сохраняется непрерывный учёт.

События сна обрабатываются последовательно с исходным временем получения. При ошибке записи
выполняются три попытки; после этого событие остаётся в очереди, а в окне доступна кнопка повтора.
До обработки новые отметки таймера не записываются. Ручное продолжение и завершение дня сначала
обрабатывают очередь и закрывают прежний цикл сна. Запоздавшее пробуждение не снимает ручную паузу.

## Восстановление после сбоя

Приложение сохраняет отметку активности при действиях пользователя и не реже одного раза
в 15 секунд во время обновления таймера. Это подтверждение работы программы, а не присутствия
человека за компьютером. После аварийного завершения показывается неизвестный интервал
от последней отметки до повторного запуска. Итоги на экране заморожены до решения пользователя.

Можно не учитывать интервал, учесть его целиком или указать длительность вручную. В последнем
случае учитывается указанное время **с начала неизвестного интервала**, а остаток исключается.
Если продолжение через полночь выключено, максимум ограничивается концом прежнего дня.
Диалог показывает этот предел, а ручной ввод сверх него отклоняется с объяснением.
Время ожидания ответа в диалоге не учитывается. После решения открытый день остаётся на паузе;
для продолжения нужно нажать «Продолжить». Если до сбоя уже была пауза, она сохраняется.
Выбранный способ записывается в журнал; распределение времени по суткам учитывает настройку
продолжения через полночь. При выходе без восстановления решение будет предложено при следующем запуске.

Настройка восстановления после штатного выхода и восстановление после сбоя независимы:
неизвестное время после сбоя требует решения даже при выключенном автоматическом восстановлении.
Если незавершённый период остался от старой версии без контрольных отметок, при обновлении
также запрашивается решение. Исходной отметкой служит последнее подтверждённое начало периода,
действие с паузой или корректировка времени открытого дня.
Диалог явно предупреждает, что промежуточных отметок в прежней версии не было и интервал
мог включать реальную работу. Кнопка исключения показывает его длительность. Причина восстановления
сохраняется при повторном открытии. Даты показаны по местному времени, длительности — без долей
секунды, для нескольких суток — например `2 дн. 03:15:00`. Точность времени в базе и JSON сохраняется.

## Сохранность данных

Повторный запуск программы открывает окно уже работающего экземпляра. При ошибке открытия
базы приложение показывает её путь, сообщение и кнопки повтора, открытия папки и выхода;
существующая база не заменяется пустой. При ошибке завершения дня можно повторить сохранение,
остаться в приложении либо явно выбрать выход без сохранения.
После ошибки открытия освобождаются соединения SQLite, чтобы повторная попытка могла открыть
исправленный или восстановленный файл базы.
Ошибки главного окна отделены от ошибок базы. Повтор открытия в том же процессе не считается
новым аварийным запуском. Если недоступны Dock или уведомления сна, учёт остаётся доступен,
а отдельное предупреждение предлагает повторить подключение.

Для расчётов границей служит ровно 00:00:00 следующих суток: последняя секунда не теряется.
В журнале автоматическое завершение относится к прежнему дню и отображается как 23:59:59.
Смена даты проверяется также после сна и при запуске; повторная проверка не создаёт дубликаты.
Границы открытого дня рассчитываются в его часовом поясе с учётом сезонного перевода часов.

Перед первым переходом старой базы на рабочие дни рядом с ней создаётся резервная копия
`worktime.db.before-workdays-<дата>-<идентификатор>.bak`. Пересекающие полночь периоды и паузы
разделяются по календарным дням с сохранением дневных итогов и журнала.

Перед обновлением непустой базы до схемы восстановления создаётся копия
`worktime.db.before-reliability-<дата>-<идентификатор>.bak`. Версия схемы хранится в
`PRAGMA user_version`; база более новой версии не открывается старой программой для записи.

JSON журнала не является полной резервной копией SQLite: импорт не восстанавливает
рабочие периоды, настройки и состояние дня. Для полного резервирования штатно завершите
приложение и сохраните копию базы из папки данных пользователя.

## Обмен журналом

При импорте журнал дополняется новыми записями. Полностью совпадающие записи пропускаются,
поэтому один файл можно импортировать повторно без появления дублей. Импорт журнала не
изменяет рассчитанное время работы и перерывов.
Новый экспорт использует версию формата 2 и сохраняет дату и состояние рабочего дня.
Импорт старых файлов версии 1 также поддерживается.

Имя экспортируемого файла содержит выбранный период, например
`WorkTimeRegister-journal-2026-10-01_2026-10-13.json`.

При экспорте сначала записывается временный файл в той же папке. Выбранный файл заменяется
только после успешной записи, поэтому ошибка экспорта не очищает предыдущий журнал.
Ошибки выбора, открытия и сохранения файлов отображаются в окне журнала. На время операции
кнопки импорта и экспорта блокируются от повторного нажатия.

Размер импортируемого JSON ограничен 128 МиБ, в том числе для потоков без возможности
определить размер заранее. Сохраняются ограничения в 100 000 записей и 1000 символов на действие.

## Инсталлятор для macOS

Для Apple Silicon:

```bash
./scripts/build-macos-installer.sh osx-arm64
```

Для Mac с процессором Intel:

```bash
./scripts/build-macos-installer.sh osx-x64
```

В каталоге `artifacts` создаются два файла:

- `.pkg` — пакет обновления, устанавливающий приложение строго в `/Applications/WorkTimeRegister.app`;
- `.dmg` — образ, содержащий тот же `.pkg` для удобной передачи.

Для первой установки или обновления откройте `.pkg`. Пакет использует постоянный идентификатор `com.worktimeregister.desktop.pkg` и атомарно заменяет предыдущую версию приложения. Предварительно удалять приложение не нужно.

Сборочные копии `.app` создаются только во временном каталоге и удаляются после упаковки, поэтому Spotlight не должен показывать их как отдельные установленные приложения. Приложение использует локальную ad-hoc подпись; для распространения без предупреждений Gatekeeper потребуются сертификат Apple Developer ID и notarization.

База данных хранится отдельно от приложения: `~/Library/Application Support/WorkTimeRegister/worktime.db`. Установщик изменяет только `/Applications/WorkTimeRegister.app` и не удаляет базу при установке или обновлении.

## Инсталлятор для Windows

Для большинства компьютеров с Windows:

```bash
./scripts/build-windows-installer.sh win-x64
```

Для Windows on ARM:

```bash
./scripts/build-windows-installer.sh win-arm64
```

Готовый самодостаточный `Setup.exe` создаётся в каталоге `artifacts`. Он не требует предварительной установки .NET и устанавливает приложение для текущего пользователя в `%LOCALAPPDATA%\Programs\WorkTimeRegister`.

Повторный запуск Setup обновляет существующую установку. База данных хранится отдельно: `%LOCALAPPDATA%\WorkTimeRegister\worktime.db`. Установка, обновление и удаление приложения не удаляют базу.

Инсталлятор создаёт ярлык в меню «Пуск» и запись `WorkTimeRegister` в списке установленных приложений Windows. Для распространения без предупреждений Microsoft Defender SmartScreen потребуется сертификат подписи кода.

При удалении используется команда приложения `--shutdown`: она запрашивает штатное сохранение
и завершение. Если приложение не завершилось, удаление отменяется; принудительный `taskkill /F`
не используется. База данных при удалении сохраняется.
