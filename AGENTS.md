# Обзор проекта

- Это Desktop-приложение, разрабатываемое на C# в IntelliJ IDEA.
- В качестве локальной базы данных используется SQLite. База данных должна оставаться лёгкой, файловой и не требовать установки отдельного сервера.
- Приложение регистрирует рабочее время в течение дня:
  - начало и конец работы;
  - начало и конец перерыва;
  - общее время работы и общее время перерывов за текущий день;
  - прошедшее время работы или перерыва для текущего активного периода.
- Итоговое время за день и длительность текущего активного периода должны отображаться постоянно и своевременно обновляться.

# Правила работы

- Перед изменением кода изучай связанные файлы и кратко объясняй пользователю план реализации.
- Не выполняй широкие рефакторинги без отдельного разрешения.
- Не переименовывай публичные API, классы, методы, DTO и endpoints без явного запроса.
- Ограничивай изменения рамками поставленной задачи и сохраняй существующее поведение за её пределами.

# Стиль C#

- Используй современный лаконичный стиль C#, согласованный с существующей кодовой базой.
- Для локальных переменных предпочитай `var`, если тип очевиден из правой части выражения.
- Комментарии в коде C# пиши на английском языке.
- Сохраняй исходный язык названий файлов, классов, методов, endpoints и ключей конфигурации; не переводи их.

# Стиль пользовательского интерфейса

- Считай пользовательский интерфейс Desktop-интерфейсом, если в проекте явно не выбран другой тип клиента.
- Следуй шаблонам и соглашениям об именовании, уже принятым в выбранном UI-фреймворке.
- Постоянно отображай и обновляй общее время работы и перерывов за текущий день, а также длительность текущего активного периода.
- Не добавляй и не заменяй UI-фреймворк без явного разрешения.

# Правила конфигурации

- Не изменяй `docker-compose.yml`, `appsettings.json` и конфигурацию frontend без отдельного разрешения.
- Не переименовывай ключи конфигурации без явного запроса.
- Храни базу данных локально и используй SQLite, если пользователь явно не согласовал другую базу данных.
- Не добавляй зависимость от отдельно устанавливаемого сервера базы данных.

# Проверка

- После изменений запускай подходящие тесты и/или сборку, если это позволяет локальное окружение.
- Указывай точные выполненные команды и их результаты.
- Если проверить изменения невозможно, чётко объясняй причину.
- При изменении соответствующей логики проверяй расчёты времени для активных рабочих периодов, активных перерывов, завершённых периодов и итогов за день.

# Формат ответа

- Всё общение с пользователем веди на русском языке.
- Весь текст файла `AGENTS.md`, включая заголовки и новые правила, пиши на русском языке.
- После изменений перечисляй все изменённые файлы.
- Указывай точные команды запуска тестов и сборки вместе с их результатами.
- Если тесты или сборка не запускались, сообщай причину.
- Не переводи названия файлов, классов, методов, DTO, endpoints и ключей конфигурации.
